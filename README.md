# ETF联接基金交易系统

纯场外 ETF 联接基金申赎的量化信号系统（易方达财富账户），包含每日盘后信号、可视化看板和盘中信号脚本。

## 架构

| 模块 | 作用 |
|---|---|
| `main.py` | 主程序：每日盘后更新数据 → 计算信号 → 生成操作提示单 + 看板 |
| `data_fetcher.py` | 数据采集：ETF场内K线(新浪+Tushare+通达信兜底) / PE估值·北向(Tushare) / 净值·跌停(AkShare) |
| `tdx_data.py` | K线数据源路由：新浪/Tushare/通达信 + xdxr精确复权 + 本地缓存 + 盘中实时行情 |
| `strategy.py` | 策略引擎：PE择时 / 动量轮动 / 移动止盈止损 / 恐慌监控 / MA20趋势闸门 / 动量持续性闸门 |
| `momentum_persistence.py` | **动量持续性过滤**：买入侧第四道闸门，回看窗口内每个交易日动量必须为正（`strategy` / `intraday_signal` / `backtest` 三处共用，口径一致） |
| `redeem_fee.py` | 场外赎回费率表（全池逐只核实）；`sell` 自动扣费、`trades.amount` 存净到账、`fee` 存实际费用 |
| `signal_exec.py` | **信号执行闭环**（2026-11-18 新增）：交易写入 `trades` 的同一事务内，把对应信号标记 `is_executed` + `executed_trade_id`，并回写 `trades.signal_source`，双向可追溯 |
| `portfolio.py` | 持仓管理、仓位计算、操作提示单、信号落库 |
| `dashboard.py` | 可视化看板生成（含盘中信号板块） |
| `intraday_signal.py` | **盘中信号核心逻辑**（共享模块，CLI 与看板复用） |
| `realtime_quotes.py` | **实时行情多渠道路由**：新浪优先/pytdx兜底(候选池) + 新浪/东财(全市场) + 优雅降级 |
| `scripts/run_intraday_signal.py` | **盘中信号CLI**（薄封装，见下） |
| `backtest.py` | 回测引擎（宽基PE择时 + 动量轮动 + 移动止盈 + MA20防守） |

## 快速开始

```bash
# 首次初始化（建表 + 拉历史数据）
python main.py init

# 每日盘后运行（约6分钟，更新数据 + 信号 + 看板）
python main.py

# 仅生成看板
python main.py dashboard

# 持仓管理
python main.py holdings                 # 查看持仓
python main.py buy 019071 --amount 100000            # 申购
python main.py confirm 019071 --shares 38595.14 --nav 2.6045   # 确认份额
python main.py sell 019071              # 赎回全部
python main.py sell 019071 --shares 5000 --fee 112.31  # 按平台实际赎回费补录(优先于费率表)
python main.py update 019071 --shares 38595.14 --cost_nav 2.5910  # 修正持仓
python main.py link-signals            # 预览历史信号↔交易关联 (dry-run, 不落库)
python main.py link-signals --apply    # 确认清单后回填历史关联
```

## 信号执行闭环（2026-11-18 新增）

此前 `signals.is_executed` / `executed_at` 自建表起从未被写入，逾期告警只能绕开它从 `trades`
反推「连续报警段之后有没有卖出成交」；系统也不知道用户在 11-09 报买后是否真的下单了。

现在**在持仓更新的那一刻就记好**：`buy` / `sell` / `update --add-shares` 写入 `trades` 后，
在同一个数据库连接、同一次 `commit` 内调用 `link_trade_to_signal()`，命中则：

- `signals.is_executed=1`、`executed_at=now`、`executed_trade_id=<trade.id>`
- `trades.signal_source` 由 `manual` 改为 `signal:<signal.id>`
- 看板今日指令打 `✅ 已执行` 标记并汇总条数，避免重复下单
- `check_unexecuted_signals()` 只统计 `is_executed=0` 的报警段

匹配口径（保守，宁可漏认领也不误认领）：方向对齐（`buy` 只认 `buy`；`sell` 认 `sell` 与宽基
`reduce`）、先按场内 `etf_code` 再兜底 `fund_code`（兼容同标的老仓/新份额）、信号日 ≤ 提交日
且相差 ≤ `SIGNAL_EXEC_LOOKBACK_DAYS=5` 个自然日、排除已执行与 reason 含「已作废」的假信号、
多候选取最近一条。未命中属正常（大量历史交易是脱离信号手动下单），保持 `manual` 不硬凑。

配套修复：`save_signals_to_db()` 原本每天 `DELETE` 当天全部信号，会把已执行标记一起抹掉；
现改为只删未执行行，并用「已执行指纹」阻止重跑主流程时把同一条指令再生成一遍。
旧库缺 `executed_trade_id` 列由 `get_connection()` 幂等迁移补齐（日常命令不走 `init_db`）。

历史数据默认**不自动回填** —— 现存 1104 条信号均为 `is_executed=0`，但其中大量是手动交易，
硬凑会污染统计。用 `link-signals`（默认 dry-run 预览）人工核对清单后再 `--apply`。

## 盘中信号脚本（当日决策 → 当日成交）

### 解决什么问题

场外申赎规则：**15:00 前提交 → 按当日收盘净值成交**。而盘后信号依赖当日收盘价，只能收盘后计算，提交后实际按 T+1 的未知净值成交——存在时间差。

利用全部决策规则（动量 / MA20 / Top3 / 持续性窗口）都**只依赖收盘价序列**的性质：在 **14:40-14:50** 用场内ETF现价当作"今日收盘价代理"计算信号，15:00 前提交，即可做到当日决策 → 当日按收盘净值成交。

盘中现价对收盘的预测误差通常 <0.3%，对动量/MA20/排名这类慢变量完全够用。持续性窗口里的历史交易日仍用真实收盘价，只有"当日"这一格是现价代理，所以**盘中口径与盘后收盘口径偶尔会给出不同结论**（例：2026-11-18 主流程喊买半导体、盘中判为无申购）。两个口径打架时不追单，以 14:40-14:50 复核结果为准。

### 用法

```bash
# 只看信号 —— 持仓状态每天自动从主系统数据库(portfolio表)读取
python scripts/run_intraday_signal.py

# 仅当数据库无持仓时才需要手动声明（基金代码:买入日期YYYYMMDD，逗号分隔）
python scripts/run_intraday_signal.py --holdings "021893:20260811,019666:20260820"

# 脚本只显示信号、不自动记账；确认在平台提交申赎后，
# 请自行用 main.py buy/confirm/sell 维护持仓系统
```

**已集成到主看板**：同一份盘中信号在 `main.py` / `main.py dashboard` 更新看板时自动计算，显示在"🕐 盘中信号"板块（实时行情、动量排名、申购/赎回/持有建议），无需单独运行。CLI 适合盘中快速查看，看板适合留档回顾。

### 输出示例

```
🟢 申购: 电网设备ETF(025856)    ← 动量Top3 + 买入四重闸门通过 且未持有
🔴 赎回: 电池ETF(012862)、半导体ETF(021893)  ← 跌出Top5缓冲区 且已过7天锁
⚪ 持有: 黄金ETF(000307)、红利低波ETF(020602)
```

### 关键机制

- **实时行情缩放**：通达信 pytdx 实时报价对 ETF/基金返回 **10倍**值（如黄金ETF报99.41，真实9.941），`tdx_data.get_realtime_quotes()` 用数据库昨收自动校准还原。
- **7天最短持有锁**：持有<7天（自然日）不触发赎回，避免 1.5% 惩罚赎回费。
- **持仓状态每日同步**：每次运行自动从主系统 `portfolio` 表读取持仓与买入日期（买入日期=份额确认日 `confirm_date`，缺失时用申购日），脚本不写任何状态、不自动记账。
- **买入闸门**（四重全满足）：① 动量Top3 ② 综合动量>0 ③ 收盘价在MA20上方 ④ 动量持续性（回看2日窗口内**每个交易日**综合动量均>0，且当日动量不低于2日前），与主系统一致；另受持仓数约束（基础3只，全部持仓仍健康时可超额至5只）。④ 只约束新买入，不改排名、不改任何卖出判定，已持仓标的不受它影响。

### 使用注意事项

1. **时效**：必须在 14:40-14:50 跑、14:50 前提交才有意义；收盘后跑只是重复当日已定的结论。
2. **临界信号**：现价对收盘是估计（<0.3% 误差），若某只ETF恰在临界（排名3/4交替、MA20贴线），建议当天不动、等次日确认。
3. **7天锁的简化**：脚本用单一"买入日期"判断持有天数；若近期有加仓，新份额的持有时间更短，赎回前请以最后一笔加仓确认日为准复核。
4. **不自动记账**：脚本只输出信号、不修改任何持仓状态；确认在平台提交申赎后，请自行用 `main.py buy/confirm/sell` 记录到持仓系统。
5. **赎回费不是满7天归零**（2026-11-12 修正）：7 天只是避开 1.5% 惩罚费率，**不等于免赎回费**。各只联接基金费率不统一，全池 22 只逐只核实后：`110020` / `008975` 的 A 类 7-364 天仍收 0.5%、`000307` 收 0.20%、3 只满 180 天归零，其余 16 只 ≥7 天已免——禁止套通用阶梯倒推。`redeem_fee.py` 登记已核实的费率表，`sell` 自动扣费并把 `trades.amount` 记为**净到账**、`trades.fee` 记实际费用；未登记费率的基金不猜，fee 记 0 但会打印告警 + remark 标记，拿平台净额后用 `--fee` 补录。历史 31 笔待核见 `data/redeem_fee_pending.json`；回测仍未计入常规赎回费，实盘年化会低于回测值。
6. **新钱走低费率份额**（2026-11-12）：全池 22 只逐只核查赎回费率后，只有 `110020` / `008975` 的 A 类在 7-364 天仍收 0.5%；其余 16 只 ≥7 天已免、4 只满 180/730 天归零（A 类长期更优，不切）。新钱申购改走 `007339`（沪深300C，≥7天0，销售服务费 0.20%/年）和 `022055`（消费50E，≥7天0，销售服务费 0.10%/年），**老仓不动**。配置在 `config.BUY_FUND_CODE_OVERRIDES`：买入/动量排名显示新代码，减仓与卖出仍指回持仓实际代码；系统按场内 `etf_code` 聚合市值，同标的两份额可共存。`redeem_fee.py` 已覆盖全池 25 个代码（含新份额）。⚠️ 首次下单前请在平台确认 007339 / 022055 可申购（022055 代销名单含易方达财富，2026-03-16 起）。
7. **动量持续性过滤**（2026-11-17 新增 / 11-18 完善）：买入侧新增第四道闸门，规则与回测对比见下方「策略规则」与「回测」。弱市里合格标的少、系统宁可空仓，是设计意图而非故障；被拦下的标的会在主流程打印 `[SKIP] …动量持续性不足` 并附上窗口内逐日动量值。

## 回测

```bash
python backtest.py                    # 默认启用 MA20防守 + 动量持续性过滤（与实盘一致）
BT_MA20_RULES=0 python backtest.py    # 关闭 MA20防守，用于 A/B 对比
BT_MOMENTUM_PERSIST=0 python backtest.py         # 关闭持续性过滤（回到 11-17 之前）
BT_PERSIST_REQUIRE_POSITIVE=0 python backtest.py  # 退回 11-17 旧口径（仅比较窗口两端）
BT_PERSIST_LOOKBACK=3 python backtest.py          # 扫回看窗口（1/2/3/5日）
```

回测区间 20240506~20260428（482个交易日），基准为沪深300买入持有（年化+14.22%，回撤15.66%）。

| 指标 | 无MA20防守 | **有MA20防守（现行）** | 差异 |
|---|---|---|---|
| 年化收益 | 19.14% | **20.71%** | +1.57pp |
| 超额收益 | +4.92% | **+6.49%** | +1.57pp |
| 最大回撤 | 9.67% | **7.97%** | 改善1.70pp |
| 盈亏比 | 1.72 | **1.90** | +0.18 |
| 卖出胜率 | 58.9% (43/73) | **61.9%** (39/63) | +3.0pp |
| 交易笔数 | 149 | **129** | -20笔 |
| 总收益 | 41.41% | **45.11%** | +3.70pp |

**结论**：MA20防守（买入闸门 + 趋势止损）在收益、回撤、胜率、盈亏比上全面占优，且交易更少。
其中 MA20趋势止损共触发6次、平均亏损-7.30%（全部为亏，但显著小于固定止损的-15.84%），
作用是把亏损截在早期——这正是它在回测中降低回撤、提升盈亏比的原因。

> 注：回测未模拟场外T+1申赎延迟，实盘执行会有时间差；可用盘中信号脚本（14:40-14:50运行）消解。**回测也未计入常规赎回费**，实盘年化天然低于回测值。

## 策略规则

### 宽基底仓（40%，2026-11-04 由 60% 下调）

沪深300 17% + 中证500 13% + 上证50 10%。PE百分位择时 + MA100趋势过滤：PE<30%且均线向上→买入，PE>80%或均线向下→减仓。

> 2026-11-04 调整说明：①宽基占比 60%→40%，动量轮动升至 60%；②科创50 换成上证50——科创50 年化波动 34.87%、历史最大回撤 -47.86%，而宽基仓位只有 PE百分位 + MA100 + 兜底 -20% 三道保护，没有个股止损，波动率明显不匹配。上证50 波动 15.67%、回撤 -22.54%。代价是 607 日样本年化让出约 3pp（实测见 `scripts/core_ratio_study.py`）。

### 行业卫星（60%，2026-11-04 由 40% 上调）
- **动量轮动**：10日动量×0.6 + 30日动量×0.4 综合排名，基础目标持有Top3；**卖出采用 Top5 排名缓冲区**，跌出Top3不硬切，只要仍在Top5内且动量>0、MA20上方就继续持有
- **买入闸门**（四重全满足）：①动量Top3 ②复合动量>0 ③收盘价在MA20上方 ④**动量持续性**：回看 2 个交易日窗口内每一天的综合动量都 >0，且当日动量不低于 2 日前（`improve` 模式）。④ 只约束新买入，不提前过滤 TopN、不改排名、不改任何卖出判定，避免误伤已持仓
- **卖出防线**（任一触发）：①移动止盈（激活8%，回撤6%）②MA20×0.95趋势止损 ③固定止损-15% ④跌出Top5缓冲区 或 动量转负/跌破MA20（持有满7天即可卖）
- **持仓上限**：卫星最多 `ROTATION_MAX_HOLD_COUNT`=5 只。超额前提：所有现有卫星持仓都还升（综合动量>0 且 收盘>MA20）；达到5只或任一持仓转弱即停止新建仓

> 2026-11-05 调整说明：取消「跌出Top3 需持有满 14 天」的轮动缓冲，改为只要过了赎回费锁（`MIN_HOLD_DAYS`=7 天）就能卖。`ROTATION_CYCLE_DAYS` 由 14 改为 7，策略层 / 盘中信号 / 回测三处自动对齐。482 日对照回测：总收益 +61.49%→+62.17%、年化 +27.42%→+27.69%、最大回撤 -9.54%→-9.01%、盈亏比 1.90→2.71，代价是卖出胜率 61.9%→46.7%、交易笔数 129→188（+46%）。收益改善有限但回撤和盈亏比更优，属于「小亏快砍、让赢单跑」的交换。复现见 `scripts/rotation_cycle_ab.py`。

> 2026-11-09 调整说明：新增**排名缓冲区 + 超额持仓**，解决「满3只 + 7天赎回费锁卖不掉 + Top3有新标的」的死锁，并压住动量排名边界抖动造成的指令来回反转。根因是 `10日动量 = 今日价/10日前价` 的分母每日滚动：11-06 机器人动量一天掉 11.88pp，其中 8.64pp 来自 10-23 一根 +8.64% 大阳线滚进分母，与当日行情无关，导致 #1→#4 后又弹回 #3。现在卖出不再按「跌出Top3」硬切，而是 `跌出Top(3+ROTATION_RANK_BUFFER)=Top5` 或 `动量≤0/跌破MA20` 才卖；买入仍只取 Top3，但允许持仓短期超过3只、上限5只，前提是全部持仓仍健康。三处同步：`strategy.check_rotation_signals` / `intraday_signal.generate_signals` / `backtest`（`BT_ROTATION_BUFFER=0` 可切回旧口径做 A/B）。

### 集中度风控（2026-09-03新增，仅提示不强制）

`SINGLE_ETF_MAX_RATIO`（12%，2026-11-05 由 8% 上调）**只约束单笔买入金额，对累计持仓没有上限**——向下摊平（越跌越买）会把单只仓位堆到远超设计的比例（实测半导体曾达总资金 59%，是单笔上限的 4.9 倍）。

因此补上累计持仓的两级预警：

| 阈值 | 级别 | 显示 |
|---|---|---|
| ≥25% | 🔴 危险 | 看板红色卡片 + 持仓表红字 |
| ≥15% | 🟡 预警 | 看板黄色卡片 + 持仓表橙字 |

- 配置：`config.py` 的 `CONCENTRATION_WARN_RATIO` / `CONCENTRATION_DANGER_RATIO`
- 实现：`portfolio.check_concentration()`（同时供操作提示单与看板调用）
- 看板：持仓区顶部预警卡片 + 持仓表「占总资金」列，均标注"减至预警线需赎回金额"

### 恐慌监控
沪深300跌幅/北向流出/跌停家数/成交量放大，≥2项触发收紧止损阈值。
